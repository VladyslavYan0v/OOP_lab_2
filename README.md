# OOP_lab_2

1. Загальний огляд проєкту
Проєкт являє собою гібридну систему, де критичні обчислення (шифрування та вимірювання метрик) виконуються на C++, а користувацький інтерфейс та взаємодія з базою даних реалізовані на Python.
Мета: Забезпечити безпечну передачу даних із детальним аналізом використання ресурсів (час, пам’ять, теоретична складність).
Інтеграція: Використано бібліотеку Pybind11 для створення бінарного модуля .pyd, що дозволяє Python викликати методи C++ безпосередньо.

2. Архітектура Backend (C++)
Система побудована на гнучкій ієрархії класів навколо інтерфейсу ICipher.  
Реалізовані алгоритми:
  RSA: Асиметричне шифрування на основі модульного піднесення до степеня.
  Shamir Protocol: Адаптація класичного протоколу через патерн Adapter.
  Caesar & XOR: Симетричні алгоритми для базового захисту.
  Комбіновані шифри: Double Secure (RSA + Shamir) та Multi-Layer Symmetric (Caesar + XOR).
Система вимірювання метрик:
Для кожного алгоритму система збирає три типи даних:
  Теоретична складність: Рядок у форматі Big O (наприклад, $O(N \cdot \log(E))$), що визначається кожним класом окремо.
  Час виконання: Вимірюється з точністю до мікросекунд за допомогою std::chrono::high_resolution_clock у декораторі.
  Використання пам'яті: Розраховується як capacity() * sizeof(int) для зашифрованого вектора.

3. Патерни проєктування (12 патернів)
У проєкті реалізовано повний спектр класичних патернів GoF:
Твірні:
  Factory Method:	CipherFactory для централізованого створення об'єктів шифрів.  
  Builder: MessageBuilder для поетапного створення складних повідомлень із різних типів даних.
Структурні:
  Adapter:	ShamirAdapter дозволяє використовувати LegacyShamir через інтерфейс ICipher.  
  Decorator:	PerformanceDecorator додає функціонал вимірювання часу та пам'яті до будь-якого шифру.  
  Composite:	CipherChain дозволяє групувати кілька алгоритмів у ланцюжок і працювати з ними як з одним об'єктом.  
  Facade:	CryptoFacade надає простий інтерфейс sendSecretMessage для складних внутрішніх процесів.
Поведінкові:
  Strategy:	Кожен алгоритм (RSA, XOR тощо) є окремою стратегією шифрування.  
  Command:	SendMessageCommand інкапсулює запит на шифрування як об'єкт для відкладеного виконання.  
  Observer:	AuditSystem підписується на події SecureDataTransfer для журналювання операцій.  
  Template: Method	SecureDataTransfer визначає фіксований алгоритм передачі (форматування -> шифрування -> заголовок).  
  Memento:	MessageMemento зберігає та відновлює внутрішній стан повідомлення.
Інші:
  Singleton:	CryptoLogger та MetricsCollector для глобального доступу до логів та статистики.

4. Frontend та База Даних
Користувацький інтерфейс (Python):
Побудований на Tkinter.
Використовує патерн Adapter для зв’язку з бінарним модулем C++.
Містить систему візуалізації кроків шифрування через canvas та анімацію.
Керування даними:
DatabaseManager: Використовує PyMySQL для збереження результатів у базу даних MySQL/MariaDB.
Відмовостійкість: Реалізовано режим Graceful Degradation — якщо база даних недоступна, програма продовжує працювати, виводячи попередження в консоль, але не припиняючи виконання основних функцій.

Проєкт демонструє успішну інтеграцію високоефективного C++ коду з гнучким Python-інтерфейсом. Завдяки використанню 12 патернів проєктування, система є легко розширюваною: додавання нового алгоритму вимагає лише створення нового класу та оновлення фабрики, не торкаючись логіки інтерфейсу чи бази даних. Реалізована система метрик дозволяє проводити реальний порівняльний аналіз криптографічних методів безпосередньо під час їх використання.
